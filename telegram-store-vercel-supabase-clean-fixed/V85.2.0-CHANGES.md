# Link Auto Order v85.2.0 - Redeem Finalization Fix + GoPay/ShopeePay Switch

## 1. Fix pesan palsu "Redeem gagal: cachedProducts is not defined"

Penyebab:
- Redeem sebenarnya sudah selesai melalui `fulfillPaidOrder()`.
- Setelah produk/receipt terkirim, flow lama masih memanggil helper `cachedProducts(true)` yang sudah tidak ada.
- ReferenceError tersebut masuk ke blok catch, sehingga user menerima pesan "Redeem gagal" walaupun transaksi sudah selesai.

Perbaikan:
- Menghapus seluruh pemanggilan `cachedProducts` dari production code.
- Menggunakan `invalidateUserFastCache()` untuk invalidasi cache user.
- Cache produk tetap diinvalidasi oleh mekanisme runtime cache ketika transaksi selesai.
- Menambahkan guard pasca-fulfillment: jika transaksi sudah tercatat, bot tidak boleh lagi mengirim pesan "Redeem gagal" akibat error finalisasi/notifikasi sesudah produk diproses.
- Jika transaksi sudah tercatat tetapi ada error lanjutan, kode redeem tetap dicoba difinalisasi tanpa me-release kode untuk dipakai ulang.

## 2. Pilihan metode pembayaran AutoGoPay di Pengaturan

Lokasi:
Dashboard Owner > Pengaturan > Metode Pembayaran

Pilihan:
- GoPay QRIS
- ShopeePay QRIS

Setting disimpan sebagai `shop_settings.autogopay_payment_method` dan default tetap `gopay`.

Pergantian hanya memengaruhi invoice baru. Invoice pending lama menyimpan `payment_provider` masing-masing sehingga tetap diverifikasi memakai metode saat invoice dibuat.

## 3. GoPay

- Generate: `POST /qris/generate`
- ID lokal: `transaction_id`
- Status: `POST /qris/status`
- Cancel pending: `POST /qris/cancel`
- Provider lokal: `autogopay`
- Label user: `QRIS GoPay`

## 4. ShopeePay

- Status koneksi: `GET /shopeepay/status`
- Generate: `POST /shopeepay/qris/create`
- ID lokal: `order_sn` disimpan ke `provider_transaction_id`
- Status pembayaran: `GET /shopeepay/qris/status?order_sn=...`
- Sukses: `paid=true` / `order_status=1`
- Provider lokal: `autogopay_shopeepay`
- Label user: `QRIS ShopeePay`

Dokumentasi AutoGoPay yang digunakan tidak mencantumkan endpoint cancel ShopeePay. Karena itu cancel invoice ShopeePay dilakukan lokal, sedangkan QR provider dibiarkan expired otomatis.

## 5. Cek Koneksi

Submenu Metode Pembayaran sekarang mempunyai tombol `Cek Koneksi`.

- GoPay: memvalidasi API key melalui endpoint daftar transaksi AutoGoPay.
- ShopeePay: memanggil `GET /shopeepay/status` dan menampilkan `connected`, `token_valid`, serta `store_id` jika tersedia.

## 6. Webhook dan polling

Webhook signed AutoGoPay tetap menggunakan verifikasi HMAC-SHA256.

`payment_method` dibedakan sebagai:
- `QRIS` -> GoPay
- `QRIS_SHOPEEPAY` -> ShopeePay

Polling/recovery lokal juga channel-aware:
- invoice GoPay -> `/qris/status`
- invoice ShopeePay -> `/shopeepay/qris/status` berdasarkan `order_sn`

## 7. Bot dan Marketplace

Caption pembayaran Telegram dan halaman pembayaran Marketplace sekarang menampilkan metode aktif:
- QRIS GoPay
- QRIS ShopeePay

Top Up juga mengikuti metode AutoGoPay yang dipilih pada Pengaturan.

## 8. Database

Tidak ada migrasi SQL baru khusus v85.2.0.

Setting metode pembayaran memakai tabel `shop_settings` yang sudah ada. Jika instalasi Anda belum pernah menjalankan migrasi v85.1 media, migrasi v85.1 tetap harus dijalankan untuk fitur gambar/video dari rilis sebelumnya.
